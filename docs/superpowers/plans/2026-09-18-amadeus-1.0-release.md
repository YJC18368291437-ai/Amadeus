# Amadeus 1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish Amadeus 1.0 as the clean, documented baseline for extending DSH with document viewing and code editing.

**Architecture:** Rename every project-owned legacy identifier across runtime routes, plugin registrations, browser storage, caches, DOM hooks, configuration, deployment templates, tests, and documentation while preserving upstream DSH package identifiers. Treat the rename as a deliberate 1.0 breaking change, validate the complete runtime, merge the release commit to `main`, and publish tag `v1.0.0`.

**Tech Stack:** Node.js 24, DSH/Cordis plugins, React 18, CodeMirror 6, PDF.js, KaTeX, SwiftLaTeX, ONLYOFFICE Document Builder, systemd, nginx.
